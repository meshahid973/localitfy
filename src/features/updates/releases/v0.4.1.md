# Localtify 0.4.1 🎧

0.4.1 is a hotfix and stability update after the big 0.4.0 release.
This update focuses on fixing Linux update behavior, improving Spotify playlist downloads, and cleaning up a few important issues that showed up after release.

0.4.0 was a huge polish update, but 0.4.1 is about making that release safer and more reliable for real users, especially on Linux AppImage builds.

## Changelog ✨

### 🐧 Linux updater behavior fixed

Linux AppImage updates are now handled more safely.

Previously, Linux builds could detect an update and cause weird startup/load issues, especially when older AppImages like 0.3.8 or 0.4.0 saw a newer release. That was not acceptable because older versions should still open normally.

For now, Linux AppImage updates are manual-only:

* Linux no longer auto-downloads AppImage updates.
* Linux no longer auto-installs or replaces the running AppImage.
* Linux update checks now show that an update exists.
* The update action opens the GitHub release page instead.
* This prevents old Linux AppImages from breaking during startup.
* Windows auto-update behavior is unchanged.

This is a safer Linux update flow until AppImage auto-update is fully reliable.

### 🎵 Spotify playlist/download improvements

Spotify playlist handling has been improved, especially when Spotify only provides weak public playlist metadata.

Changes include:

* Improved Spotify-to-YouTube matching logic.
* Added more fallback search attempts for Spotify tracks.
* Added a direct search fallback when safe candidate matching cannot find results.
* Reduced instant “Could not safely match this Spotify track” failures.
* Improved handling for tracks where public Spotify fallback does not include proper artist data.
* Improved Spotify download messages so failed matches are easier to understand.
* Fixed cases where a track could fail before yt-dlp even had a chance to search properly.

Spotify downloads should now be less strict and more useful while still trying to avoid completely wrong matches.

### 📁 Album import fixes

Album importing was improved after users found that importing a folder with many albums could group everything incorrectly.

Fixes include:

* Fixed recursive album folder detection.
* Prevented parent folders from becoming one giant album.
* Improved album detection for folders containing multiple separate albums.
* Improved folder-based album titles.
* Improved handling for artist folders containing album folders.
* Added better behavior for re-importing album folders.
* Reduced duplicate/stale album entries after re-imports.

This should make large album folder imports behave much more naturally.

### 🗑️ Album actions and cleanup

Album management received some small but important cleanup.

Added/improved:

* Delete selected album actions.
* Delete all albums action.
* Safer confirmation before clearing albums.
* Cleaner album import status messages.
* Better empty album states.
* Less clutter when no albums exist.
* Better handling for generated/custom/folder/tag albums.

Album pages should now feel less messy and easier to manage.

### 🔁 Repeat-one playback fix

Fixed an issue where repeat-one could play another song instead of restarting the current song.

Changes include:

* Repeat-one now restarts the same track properly.
* Crossfade/preload behavior no longer steals playback from repeat-one.
* End-of-track handling is safer for looped songs.

### 🎨 Custom theme persistence

Fixed an issue where custom theme settings could disappear after updating.

Changes include:

* Custom theme settings are backed up locally.
* Custom theme colors are restored after app updates.
* App update/default settings migrations should no longer wipe custom theme choices.

### 🎛️ Player and UI polish

Small player and UI fixes were added after 0.4.0.

Changes include:

* Improved play/pause morph button behavior.
* Improved player button sizing.
* Improved repeat/shuffle icon polish.
* Improved queue/player badge alignment.
* Reduced some expensive player blur/glow behavior.
* Reduced unnecessary progress-related re-rendering.
* Improved player performance while music is playing.

### 🚀 Performance and stability

0.4.1 includes smaller stability fixes after the large 0.4.0 performance work.

Changes include:

* Reduced unnecessary renderer update work.
* Improved progress update timing.
* Reduced player visual cost in heavier states.
* Improved Linux startup safety.
* Improved packaged build behavior.
* Improved main/preload bridge reliability.
* Reduced risk from Linux updater behavior.

### 🪟 Windows

Windows update behavior remains normal.

Windows still supports the normal installer/update metadata flow through:

* `localtify-setup-0.4.1.exe`
* `localtify-setup-0.4.1.exe.blockmap`
* `latest.yml`

### 🐧 Linux release note

Linux AppImage users should download updates manually from GitHub releases.

Linux release should include:

* `localtify-0.4.1-x86_64.AppImage`

Linux release should not include `latest-linux.yml` for now, because Linux AppImage auto-update is disabled until it is fully safe.

## Thank you 💖

Thank you to everyone using Localtify and testing the app across Windows and Linux.

0.4.1 is not meant to be a huge feature update. It is a safety and reliability patch to make the 0.4.0 release better for real users.

The goal is still the same: make Localtify feel like a cute, smooth, reliable local music library app.
